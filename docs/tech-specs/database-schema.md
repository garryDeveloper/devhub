# Database schema

PostgreSQL 16. EF Core code-first; this document describes the intended physical model.

---

## 1. Global rules

- Table and column names are `snake_case`; tables are plural. Configure the naming convention
  once (`EFCore.NamingConventions` → `UseSnakeCaseNamingConvention()`), never rename by hand.
- Primary keys are `uuid` generated by the application (v7 for index locality), not `serial`.
- Timestamps are `timestamptz`, always stored UTC. Never `timestamp without time zone`.
- Enums are stored as `text` with a `CHECK` constraint, not as PostgreSQL enum types and not as
  integers — readable in psql, safe to extend, no migration pain when reordering.
- Every foreign key declares its delete behaviour explicitly. Default is `RESTRICT`; `CASCADE`
  only where the child cannot exist alone.
- Money, counters and sequences are `integer`/`bigint`, never `float`.
- Soft delete (`archived_at`) exists **only** on `projects` and `issues`. Everything else is a
  hard delete.

## 2. Tables

### users

| Column | Type | Constraints |
|---|---|---|
| id | uuid | PK |
| email | citext | UNIQUE NOT NULL |
| display_name | varchar(100) | NOT NULL |
| avatar_key | varchar(512) | NULL (S3 key) |
| password_hash | text | NOT NULL |
| created_at / updated_at | timestamptz | NOT NULL |

`citext` extension gives case-insensitive uniqueness without lowercasing tricks.

### refresh_tokens

| Column | Type | Constraints |
|---|---|---|
| id | uuid | PK |
| user_id | uuid | FK → users ON DELETE CASCADE |
| token_hash | varchar(64) | UNIQUE NOT NULL (SHA-256 hex) |
| expires_at | timestamptz | NOT NULL |
| revoked_at | timestamptz | NULL |
| replaced_by_token_id | uuid | NULL, FK → refresh_tokens |
| created_by_ip | inet | NULL |
| user_agent | varchar(400) | NULL |
| created_at | timestamptz | NOT NULL |

Index: `(user_id, expires_at)`. Purge revoked/expired rows older than 60 days.

### workspaces

`id`, `name varchar(80)`, `slug varchar(50) UNIQUE`, `owner_id uuid FK users`,
`created_at`, `updated_at`.

### workspace_members

`id`, `workspace_id FK CASCADE`, `user_id FK CASCADE`, `role text CHECK (role IN ('Owner','Member'))`,
`joined_at`. UNIQUE `(workspace_id, user_id)`. Index `(user_id)` — every authorization check
starts from the user.

### projects

| Column | Type | Constraints |
|---|---|---|
| id | uuid | PK |
| workspace_id | uuid | FK → workspaces ON DELETE CASCADE |
| name | varchar(80) | NOT NULL |
| key | varchar(10) | NOT NULL, CHECK `key ~ '^[A-Z][A-Z0-9]{1,9}$'` |
| description | varchar(2000) | NULL |
| color | char(7) | NULL |
| icon | varchar(40) | NULL |
| issue_sequence | integer | NOT NULL DEFAULT 0 |
| archived_at | timestamptz | NULL |
| created_at / updated_at | timestamptz | NOT NULL |

UNIQUE `(workspace_id, key)`. Index `(workspace_id) WHERE archived_at IS NULL`.

### project_members

`id`, `project_id FK CASCADE`, `user_id FK CASCADE`, `role text`, `added_at`.
UNIQUE `(project_id, user_id)`.

### labels

`id`, `project_id FK CASCADE`, `name varchar(40)`, `color char(7)`, `created_at`.
UNIQUE `(project_id, lower(name))`.

### issues

| Column | Type | Constraints |
|---|---|---|
| id | uuid | PK |
| project_id | uuid | FK → projects ON DELETE CASCADE |
| number | integer | NOT NULL |
| key | varchar(20) | NOT NULL (denormalized `DEV-42`) |
| title | varchar(200) | NOT NULL |
| description | text | NULL |
| status | text | NOT NULL CHECK in the 6 statuses |
| priority | text | NOT NULL CHECK in the 5 priorities |
| assignee_id | uuid | NULL FK → users ON DELETE SET NULL |
| reporter_id | uuid | NOT NULL FK → users ON DELETE RESTRICT |
| due_date | date | NULL |
| search_vector | tsvector | GENERATED (see [`search-spec.md`](search-spec.md)) |
| archived_at | timestamptz | NULL |
| created_at / updated_at | timestamptz | NOT NULL |

UNIQUE `(project_id, number)`, UNIQUE `(key)`.

Indexes:

```sql
CREATE INDEX ix_issues_project_status   ON issues (project_id, status)   WHERE archived_at IS NULL;
CREATE INDEX ix_issues_project_updated  ON issues (project_id, updated_at DESC);
CREATE INDEX ix_issues_assignee_status  ON issues (assignee_id, status)  WHERE assignee_id IS NOT NULL;
CREATE INDEX ix_issues_search           ON issues USING GIN (search_vector);
```

### issue_labels

`issue_id FK CASCADE`, `label_id FK CASCADE`, `added_at`. PK `(issue_id, label_id)`.
Index `(label_id)` for filtering by label.

### comments

`id`, `issue_id FK CASCADE`, `author_id FK users RESTRICT`, `body text NOT NULL` (≤10 000),
`created_at`, `updated_at`, `edited_at NULL`. Index `(issue_id, created_at)`.

### issue_activities

`id`, `issue_id FK CASCADE`, `actor_id FK users RESTRICT`, `type text NOT NULL`,
`old_value varchar(200) NULL`, `new_value varchar(200) NULL`, `metadata jsonb NULL`,
`created_at`. Index `(issue_id, created_at DESC)`. **Append-only** — no UPDATE, no DELETE.

### attachments

`id`, `issue_id NULL FK CASCADE`, `comment_id NULL FK CASCADE`, `uploaded_by_id FK users`,
`file_name varchar(255)`, `content_type varchar(120)`, `size_bytes bigint`,
`storage_key varchar(512) UNIQUE`, `status text CHECK ('Pending','Ready','Failed')`, `created_at`.

```sql
CONSTRAINT ck_attachment_owner CHECK (num_nonnulls(issue_id, comment_id) = 1)
```

Index `(status, created_at) WHERE status = 'Pending'` for the 24 h GC job.

### environments

`id`, `project_id FK CASCADE`, `name varchar(50)`, `type text CHECK ('Development','Staging','Production')`,
`url varchar(500) NULL`, `current_version varchar(50) NULL`,
`health_status text CHECK ('Unknown','Healthy','Degraded','Unhealthy') DEFAULT 'Unknown'`,
`last_deployed_at timestamptz NULL`, `sort_order int`, `created_at`, `updated_at`.
UNIQUE `(project_id, lower(name))`.

### deployments

| Column | Type | Constraints |
|---|---|---|
| id | uuid | PK |
| environment_id | uuid | FK → environments ON DELETE CASCADE |
| number | integer | NOT NULL (per project) |
| version | varchar(50) | NOT NULL |
| commit_sha | varchar(40) | NULL |
| commit_url | varchar(500) | NULL |
| branch | varchar(200) | NULL |
| status | text | NOT NULL CHECK in the 5 statuses |
| triggered_by | varchar(100) | NULL |
| release_id | uuid | NULL FK → releases ON DELETE SET NULL |
| cicd_run_id | uuid | NULL FK → cicd_runs ON DELETE SET NULL |
| external_id | varchar(100) | NULL (provider id, for idempotency) |
| started_at / completed_at | timestamptz | NULL |
| duration_ms | integer | NULL |
| metadata | jsonb | NULL |
| created_at | timestamptz | NOT NULL |

UNIQUE `(environment_id, external_id) WHERE external_id IS NOT NULL` — this is what makes the
webhook idempotent. Index `(environment_id, created_at DESC)`.

### deployment_events

`id`, `deployment_id FK CASCADE`, `name varchar(120)`, `status text`, `message text NULL`,
`occurred_at timestamptz`. Index `(deployment_id, occurred_at)`. Append-only.

### releases

`id`, `project_id FK CASCADE`, `version varchar(50)`, `name varchar(120) NULL`, `notes text NULL`,
`status text CHECK ('Draft','Released','Archived')`, `published_at timestamptz NULL`,
`created_by_id FK users`, `created_at`, `updated_at`. UNIQUE `(project_id, version)`.

### release_issues

`release_id FK CASCADE`, `issue_id FK CASCADE`, `added_at`. PK `(release_id, issue_id)`.
Partial unique index enforcing "one released release per issue":

```sql
CREATE UNIQUE INDEX ux_issue_single_released_release
  ON release_issues (issue_id)
  WHERE release_id IN (SELECT id FROM releases WHERE status = 'Released');
```

(If the subquery form is rejected, enforce it in the domain and add an integration test.)

### cicd_runs

`id`, `project_id FK CASCADE`, `provider text`, `external_id varchar(100)`,
`workflow varchar(200)`, `run_number integer`, `branch varchar(200)`, `commit_sha varchar(40)`,
`commit_url varchar(500)`, `run_url varchar(500)`, `status text`, `started_at`, `completed_at`,
`duration_ms int NULL`, `created_at`.
UNIQUE `(project_id, provider, external_id)`. Index `(project_id, created_at DESC)`.

### notifications

`id`, `user_id FK CASCADE`, `type text`, `title varchar(200)`, `body varchar(1000) NULL`,
`target_type text`, `target_id uuid`, `read_at timestamptz NULL`, `created_at`.
Index `(user_id, created_at DESC)`, partial index `(user_id) WHERE read_at IS NULL` for the badge.

### issue_filters

`id`, `project_id FK CASCADE`, `user_id FK CASCADE`, `name varchar(80)`, `query varchar(1000)`,
`created_at`. UNIQUE `(project_id, user_id, lower(name))`.

### webhook_deliveries (audit, DEVHUB-068)

`id`, `source text`, `external_id varchar(200)`, `signature_valid boolean`,
`payload jsonb`, `status_code int`, `received_at`. Index `(source, external_id)`.
Retain 30 days. Used to debug webhooks and to prove idempotency.

```sql
-- uuid generation happens in the application, no extension needed
```

## 4. Sequence generation for issue keys

Race-safe, without a table lock:

```sql
UPDATE projects
   SET issue_sequence = issue_sequence + 1
 WHERE id = @projectId
RETURNING issue_sequence;
```

Run inside the same transaction as the issue insert. The returned number becomes
`issues.number` and `key = project.key || '-' || number`. Deleting an issue never reuses a
number. Deployment numbers follow the same pattern with a per-project counter.

## 5. Migration rules

- One migration per ticket, named after it: `20260906_DEVHUB042_AddIssueStatusIndex`.
- Migrations must apply cleanly to an empty database **and** to the previous version.
- Never edit an applied migration. Add a new one.
- Destructive changes (drop column, narrow a type) are split: deploy code that stops using it,
  then drop it in a later migration.
- Seed data (default environments) is created by application code, not by migrations, so it
  respects domain rules.
- Every migration is exercised by the integration test suite against a real PostgreSQL container.
